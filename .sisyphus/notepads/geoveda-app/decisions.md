### Key Architectural Choices

**1. Role Storage Strategy:**
- ✅ Roles stored in Convex users table (NOT just JWT)
- ✅ Enables immediate role change effect
- ✅ Server-side lookups in every mutation/query

**2. Admin Bootstrap:**
- ✅ Priority 1: ADMIN_WALLET_ADDRESSES env var
- ✅ Priority 2: First user becomes admin
- ✅ Self-protection: admin cannot demote self

**3. Lot Number Generation:**
- ✅ Server-generated (not client-provided)
- ✅ Format: LOT-YYYYMMDD-XXXXXX (date + random 6-char)
- ✅ Prevents collision attacks

**4. Step Permissions:**
- ✅ Hardcoded role-to-step-type mapping
- ✅ farmer → harvest
- ✅ processor → process, quality_check
- ✅ distributor → transport
- ✅ retailer → receive, retail
- ✅ admin → all

**5. Status Transitions:**
- ✅ created (initial) → in_progress (first step) → complete (retail step)
- ✅ Auto-updated based on step additions

**6. Public Trace:**
- ✅ No authentication required
- ✅ Sanitized response (no wallet addresses, only roles)
- ✅ Timeline sorted by timestamp

**7. Phase 5 Scope:**
- ✅ Documentation ONLY (no on-chain code)
- ✅ Keccak-256 hash specification
- ✅ Anchoring flow design
- ✅ Verification strategy
- ✅ Future implementation ready
